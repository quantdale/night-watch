only for narrowly bounded PHP helper/resource/DTO flows that can be resolved

complete branches, and deterministic response-shape proof. Compose the Phase 26

## Required proof contract

Every admitted interprocedural join must bind an exact callsite, exact named
target, one unambiguous declaration, approved repository/path, current source
identity and inspected-content digest, bounded supported syntax, complete
branch behavior, deterministic response derivation, and sanitized caller-to-
declaration-to-contract lineage. Dynamic dispatch, magic methods, factories,
reflection, eval, variable callables, ambiguous imports/inheritance/traits,
runtime configuration, unresolved framework behavior, recursion, and cycles
remain exclusions.

Use an explicit small depth budget, preserve branch completeness, and fail
closed with categorical diagnostics. Relevant declaration changes invalidate
dependent proofs; unrelated changes do not churn unaffected proofs. Cache
identity must include analyzer/dependency identity and exact currentness.
Phase 24 remains the sole portfolio/eligibility authority and response proof
never implies read-only safety.

## Acceptance shape

taxonomy, a bounded exact interprocedural implementation or an evidence-based
hardening fallback, integrated graph/currentness/cache/operator behavior,
positive and negative adversarial controls, privacy and determinism proof,
synthetic source-to-Phase24-to-replay/dossier integration, quantitative before/
after accounting, authoritative local and clean-checkout validation, complete
continuity documentation, and synchronized clean `main`.
