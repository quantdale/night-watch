## Intent

Use a fresh approved-source census to make Nightwatch's source intelligence
more sound, explainable, measurable, deterministic, currentness-safe,
privacy-safe, resource-bounded, and resistant to adversarial PHP. Admit a new
exact proof family only if current approved source demonstrates a bounded,
mechanically complete family that passes the explicit admission gate. A zero
coverage increase is correct when the evidence supports hardening instead.

## Required outcome

Deliver a coherent local/source/synthetic capability slice across the existing
source scan, response/semantic analyzers, dependency graph, cache and
invalidation, review/explain surfaces, Phase 24 adapter, operator CLI, quality
gates, and synthetic campaign. Persist only sanitized structural metadata:
bounded categories, counts, safe identities, paths already permitted by the
source descriptors, and digests. Raw sibling source and runtime values remain
ephemeral.

The fresh census must reproduce current truth and provide deterministic gap
aggregates answering which repositories, languages, route/handler categories,
analyzer families, syntax/control-flow/return/declaration families, lexical or
budget limits, currentness states, and ambiguity classes dominate remaining
proof gaps. Human-readable and JSON operator output must describe the same
bounded facts.

## Admission gate

A new proof family is admitted only if it exists in current approved source,
has meaningful bounded value, binds producer and consumer exactly, proves all
reaching branches, has exact current dependencies, needs no PHP execution,
framework emulation, service container, fuzzy matching, deployment inference,
or read-only inference, has deterministic invalidation, is path-confined,
privacy-safe, resource-bounded, and has adversarial falsification tests.

The preferred candidate is a single-function local producer/alias flow. The
fresh 2026-08-25 census found no strict direct literal producer candidate:
current variable-return handlers are dominated by control-flow (34), multiple
assignments (16), no local assignment (12), and opaque assignment (4), with
zero strict one-assignment/no-control-flow candidates. Therefore no producer
flow authority is admitted speculatively in this task unless a later,
mechanically verified census contradicts this evidence.

## Scope

- fresh six-repository census and deterministic rejection taxonomy;
- precise, bounded response-flow rejection categories and diagnostic wiring;
- lexical/token/function/declaration resource hardening without silent proof;
- dependency, currentness, cache, invalidation, and deterministic-order tests;
- privacy and adversarial PHP corpus expansion with hard-zero false-positive
  acceptance;
- source-surface, review/explain, operator, graph, Phase 24, quality-gate, and
  synthetic integration;
- complete local and disposable clean qualification, documentation, and
  synchronized `main` closure.

## Non-goals

No generic PHP data-flow engine, PHP execution, framework/container inference,
namespace/import/inheritance/trait/magic/reflection/eval/factory authority,
runtime equivalence, read-only classification from response shape, DEV/NEXT or
production contact, datastore/cloud/infrastructure work, Alphaus mutation,
publication, real campaign, canonical self-development promotion, or parallel
portfolio authority.

## Safety constraints

All sibling reads use the existing confined read-only boundary. Unknown,
dynamic, ambiguous, stale, malformed, oversized, cyclic, or budget-exhausted
behavior fails closed before any proof or executor callback. Diagnostics use a
bounded enum/category vocabulary and never include source fragments, token
text, exception text, literal values, credentials, cookies, authorization
strings, or customer data. Phase 24 remains the sole candidate/portfolio
authority; response/semantic proof does not prove operation safety.

## Acceptance shape

The final task must contain a fresh census, a recorded proof-family decision,
precise gap and rejection measurements, currentness/cache/determinism tests,
resource-bound and privacy/adversarial fixtures, integration through existing
operator and portfolio seams, all required validation gates, continuity-v2
closure, documentation truth, a detailed report, and clean synchronized
`main`. If no exact family is admitted, the report must say so explicitly and
rank the remaining gaps without treating reclassification as coverage.
