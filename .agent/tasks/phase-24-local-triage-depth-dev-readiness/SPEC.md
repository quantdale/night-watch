# Phase 24 Specification

Task ID: phase-24-local-triage-depth-dev-readiness
Phase: 24-LOCAL-TRIAGE-DEPTH-DEV-READINESS
Title: Nightwatch Phase 24 — Local Autonomous Triage Depth and DEV-Readiness Acceleration
Status: IN_PROGRESS
Authorization class: PHASE_24_LOCAL_AUTONOMOUS_TRIAGE_DEPTH_AND_DEV_READINESS_ONLY
CONTINUITY_PROTOCOL_VERSION: nightwatch.agent-continuity.v2

## Intent

Make Nightwatch materially better at deterministic, source-backed local bug
triage while the exact-head GitHub Actions gate is externally blocked. The
implementation must reduce the remaining work needed for a future bounded DEV
observation without treating local success as external-CI authority.

## Required outcome

Deliver a coherent local/source/synthetic capability slice spanning as many of
the requested Phase 24 workstreams as the current architecture safely
supports: a larger and more explainable candidate portfolio, currentness and
manifest binding, no-contact campaign rehearsal, deeper semantic and bounded
cross-surface checks, replay/minimization and dossier improvements, component
provenance, source-change invalidation, privacy sentinels, operator blockers,
conservative CI-state observability, lifecycle hardening, clean-checkout
reproducibility, campaign breadth, and one meaningful additional local
capability. Prefer pure cores and synthetic adapters over new authority seams.

## Authority and safety

- Alphaus repositories are read-only inputs only; no sibling write is allowed.
- No production, NEXT, cloud, Kubernetes, database, datastore, IAM, or
  infrastructure operation is in scope.
- No credentials, authentication state, customer values, raw bodies, DOM,
  screenshots, traces, or private evidence may enter Git, task files, receipts,
  manifests, replay plans, dossiers, findings, or diagnostics.
- Semantic authority remains deterministic and source/provenance bound. No AI,
  self-development, or generic guessing enters the oracle authority path.
- Unknown operation, mutation, environment, source, policy, or CI states fail
  closed. Zero-step Actions remains an external blocker, never green.
- Any real DEV decision must use the existing fresh exact-head pre-DEV chain;
  this task does not grant standing DEV or authentication authority.

## Design constraints

Reuse established Phase 9A.1/10 source admission, Phase 20/21 semantic
coverage, Phase 22 candidate/manifest, Phase 23 quality-gate, and existing
triage/replay/dossier seams. Do not add extractor kinds or relabel synthetic
expectations as real-source authority. New artifacts must have bounded schema,
canonical serialization, deterministic digests, explicit freshness, and
privacy-minimal projections. Candidate order must not affect identity unless
the order is itself a declared semantic input.

## Non-goals

No CI billing workaround, no repeated external observation, no changes to the
frozen infrastructure/data-plane policy, no product-networking semantic change,
no external publication or coordination, no broad historical phase rewrite,
and no attempt to certify a real DEV result while Actions is not an executed
exact-head green run.

## Acceptance shape

Focused tests prove reason-code completeness, exclusion safety, canonical
manifest identity, no-contact rehearsal, semantic/cross-candidate negative and
benign fixtures, replay divergence categories, minimization preservation,
dossier privacy, ownership ambiguity, source-change invalidation, CI
classification, operator diagnostics, lifecycle interruption, and fixture
repeatability. Stabilization runs the repository quality gate, typecheck,
hardening, continuity/project checks, synthetic campaign, owner provenance,
clean-checkout qualification, and required canonical/isolated parity checks.
